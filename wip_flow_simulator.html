IAT < bottleneck PTJobs arrive faster than the bottleneck can process them. Throughput cannot rise above 1 / bottleneck PT, so every extra arrival simply joins the queue: WIP accumulates in front of the bottleneck and keeps growing for as long as the line runs.
IAT = bottleneck PTArrivals are paced exactly to the bottleneck. In this zero-variability line no WIP builds up anywhere, the bottleneck runs at 100% utilisation and throughput equals the maximum capacity, 1 / bottleneck PT.
IAT > bottleneck PTThere is still no WIP, but the bottleneck now waits for work. Throughput falls to 1 / IAT, below what the line could produce: the gap is throughput lost for good.

Definitions. Buffer WIP is jobs that have arrived at a station but have not started service. Station WIP = buffer + any job currently in service. Observed utilisation is exact busy time after the warm-up divided by (T − warm-up). Throughput is likewise counted only for jobs finishing after the warm-up, so the start-up period, when the line is still filling, does not count as lost output. *Nominal long-run utilisation uses steady flow limited by all preceding capacities; at/behind an overloaded bottleneck it reflects the attainable deterministic flow. Infinite buffers, one job per server, no blocking, first external arrival at t=0, and instantaneous transfer between stations are assumed.

Pacing arrivals to the bottleneck. With no variability, the best IAT is exactly the bottleneck processing time. Set IAT equal to the bottleneck PT and the line carries no WIP while still reaching maximum throughput. Set it any higher and throughput is lost, because the bottleneck sits idle between arrivals. Set it any lower and throughput does not improve at all: the extra jobs only pile up as WIP in front of the bottleneck, growing by (1/IAT − 1/PTbottleneck) jobs per time unit.

Adding variation. Each random time is drawn from a lognormal distribution with the set mean and CV, so means and bottleneck stay the same and only the variability changes. With variation on, the throughput box shows the mean over the chosen number of replications (white marker = the same line with no variation), while the schematic and table show replication 1. Variation can only hurt: a stage that runs fast for a while cannot bank that time, and a slow spell upstream starves the bottleneck, so time it loses is never recovered. At IAT = bottleneck PT the line now loses throughput and builds WIP. Raising the IAT gives slack that keeps queues bounded, but costs throughput. Variability always has to be paid for with inventory (WIP), spare capacity, or lost throughput.

How much WIP? (WIP cap mode) Under a WIP cap (CONWIP) a new job is released only when a finished one leaves, so WIP is set directly instead of being a side-effect of the IAT. The critical WIP W₀ = rb × T₀ (bottleneck rate × total processing time of one job) is the smallest WIP that gives maximum throughput when there is no variation. With variation, more WIP is needed to protect the bottleneck from starving. The chart shows how much, and the WIP needed is the smallest WIP whose throughput meets the customer demand set at the top. Beyond that, Little's Law (WIP = throughput × cycle time) means extra WIP mostly adds cycle time. Reference curves: best case TH = min(w/T₀, rb); practical worst case TH = w/(W₀ + w − 1) × rb (Hopp & Spearman, Factory Physics). Throughput is counted after the warm-up, so start-up does not count against either strategy.
