Push vs Pull

How much work-in-process does a line really need, and what happens when we get it wrong?

Little's Law · critical WIP · CONWIP · the cost of variation

Frame the question: every line holds some WIP. Too little starves the bottleneck, too much only adds waiting. The two release strategies handle this very differently.
The example

One line, six servers, one bottleneck

Bottleneck rate rb3.33jobs / time unit = 1 / 0.30
Raw process time T01.41time units for one job, no waiting
Customer demand3.00jobs / time unit = 90% of capacity
Point at S5: it alone sets the maximum output, 3.33 jobs per time unit. Demand is 3.0, so the line has 10% spare capacity. T0 is the sum of all six processing times.
Two release strategies

Who decides when a job enters the line?

Push · fixed interarrival time

A schedule releases jobs

You set the release rate. WIP is whatever builds up, here in front of the bottleneck.

Pull · WIP cap (CONWIP)

A customer order lets the next job in

You set the WIP cap. Each delivery sends an order back to the start, so WIP never exceeds it.

Watch both lines for a few seconds. Push keeps releasing on the clock, so jobs pile up in front of the bottleneck until the animation restarts. Pull only starts a job when an order comes back from the customer, so the line never holds more than four. Jobs start grey and turn gold as they are completed.
Tools for the rest of the lecture

Three relationships

Little's LawWIP = TH × CT

Average WIP equals throughput times average cycle time, in any line that has settled down. Fix two and the third follows.

Capacity ceilingTH ≤ rb

No release rule can lift throughput above the bottleneck rate, 3.33 here. Extra WIP above that point only waits.

Critical WIPW0 = rb × T0

3.33 × 1.41 = 4.7 jobs. The smallest WIP that gives full throughput when nothing varies.

W0 is Little's Law applied at the ideal point: maximum throughput with zero waiting, so cycle time equals T0.

Push vs pull · WIP over time

How WIP behaves while the line runs

Jobs inside the line · mean of 20 runs · 50% CV
  • WIP costs money. Every job in the line adds holding cost and ties up capital in material and labour that cannot be sold yet.
  • Push at IAT 0.33 keeps WIP near 8, but uses only 90% of the line's capacity: 3.00 of 3.33 jobs per time unit.
  • Shorten the IAT to 0.30 and WIP goes through the roof: from 10 to 33 jobs, and still rising when the run ends.
  • Pull holds WIP exactly at the cap you set, however long the line runs.

The real difference

What happens when you get the setting wrong?

Push error

Release 10% faster than capacity: WIP grows from 61 to 210 jobs and keeps climbing.

Pull error

Allow 50% too much WIP (12 instead of 8): WIP stays at 12, cycle time rises 43%.

Pull's mistakes are bounded. Push's are not.

Try it · WIP & Flow SimulatorAll CVs 50%: compare Push IAT 0.27 with Pull WIP 12 at run times 250, 500 and 1000.one run per point · warm-up 10% of run
This is the slide to remember. Capacity is hard to know exactly, so the release rate in push is a guess. WIP is easy to count, so the cap in pull is a setting you can see and hold.
Choosing a strategy

When to use which

Push fits when
  • demand sits well below capacity
  • processes are regular and capacity is well known
  • release dates must follow a plan, such as MRP or due dates
Pull fits when
  • processing times vary or capacity is uncertain
  • short, predictable lead times matter to the customer
  • WIP must be capped for space, cash or quality reasons

Many plants combine them: plan with push, then release to the floor under a WIP cap.

Our example favoured push more than many real lines would, because arrivals were perfectly regular. Real releases vary too, which widens the gap.

Takeaways

Three things to remember

  • 1The bottleneck caps throughput. WIP above what the bottleneck needs only adds waiting time.
  • 2Without variation the line needs only the critical WIP, W0 = rb × T0. Variation raises that number.
  • 3Variation is paid for with WIP, spare capacity or lost output. Pull lets you choose the WIP and holds it there; push leaves it to chance.
